# 十一大省钱策略详解

> 本文档是麦麦省钱助手的核心方法论。执行点餐任务时按需套用，
> 所有优惠金额必须来自工具实际返回值，**禁止虚构或预估折扣**；
> 涉及团购比价的估算值必须明确标注。

## 策略 1：领券前置 —— 先领后点

```
available-coupons        # 查用户当前可领取的麦麦省券
→ 展示券列表 → 用户同意 → auto-bind-coupons（一键领取全部可领券）
→ query-my-coupons       # 确认领取结果
```

- `auto-bind-coupons` 是**写操作**，执行前必须获得用户确认。
- 领完券再下单，后续 `query-store-coupons` 才可能查到新券。

## 策略 2：门店选券 —— 券和订单类型强相关

```
query-store-coupons      # 指定门店 + orderType：1=到店（含得来速），2=外送（含团餐）
```

- 同一张券可能只在到店或外送可用；切换就餐方式后要**重新查券**。
- 结合 `query-my-coupons` 全量资产，筛选对当前购物车最优的券。

## 策略 3：双价对比 —— 每次报价都带省钱明细

```
calculate-price（不带券）→ calculate-price（带最优券组合）
```

输出模板：

```
商品原价：¥39.5
优惠券： -¥10.0（券名）
实付：    ¥29.5   （节省 ¥10.0 / 25%）
```

- 有多个可行组合时，选实付最低者并说明理由。
- 每一笔优惠必须来自 `calculate-price` 返回，不得心算预估。

## 策略 4：套餐替换 —— 零成本升级/降本

```
query-meal-detail        # 查套餐组成与可替换项
```

- 优先推荐**价格不变**的替换（如中可乐 → 零度可乐），既省钱又契合健康需求。
- 替换信息要进入 `calculate-price` 与 `create-order` 的商品参数。

## 策略 5：积分抵扣 —— 让积分变餐费

```
query-my-account         # 可用积分 + 即将过期积分（过期前 30 天内主动提醒）
→ mall-points-products   # 检索同款/同类餐品券（shopId=2 类目）
→ mall-product-detail    # 确认 SKU 与兑换价
→ 对比：积分兑换 vs 现金+券
```

- 估算口径：1 积分 ≈ 0.01 元，实际以商品页返回为准。
- 即将过期积分是最高优先级的消耗理由。

## 策略 6：卡类随单 —— 高频用户的长期省钱

```
order-list               # 看近期下单频次
```

- `create-order` 支持随单购买麦金卡/早餐卡（v1.0.6+）。
- 频繁点早餐 → 建议评估早餐卡；月点单 ≥ 4 次 → 建议评估麦金卡。
- 卡类价值取决于使用频次，**必须向用户说明"仅当使用 N 次以上才划算"**。

## 策略 7：活动情报 —— 蹭官方活动

```
now-time-info            # 先对齐当前时间
→ campaign-calendar      # 当月营销活动：进行中/未来日期
```

- 活动信息（如指定日期满减、限定套餐）要主动融入点餐建议。

## 策略 8：积分抽奖 —— 消化沉睡积分

```
query-lottery-info       # 活动状态、消耗规则、单次积分、剩余可抽次数、免费次数
→ 有免费次数或用户确认后 → draw-lottery（写操作，需确认）
→ query-my-prizes        # 查奖品
```

- **有免费抽奖次数时必须提醒用户**（零成本机会）。
- 消耗积分抽奖前，先与策略 5 对比：这些积分直接换券是否更划算。

## 策略 9：团餐促销 —— 满减/满折叠加

```
query-promotions         # 仅团餐场景(beType=6)，当前门店有效的满减/满折
→ query-meal-assistance  # 助餐服务
→ query-meals            # 按预算档位搭配（工具描述含 20 元以下等搭配规则）
→ calculate-price
```

## 策略 10：答卷回收 —— 不放过已产生的奖券

```
query-survey-coupon      # 按订单号查满意度答卷关联奖券的核销状态
```

- 用户查历史订单（`order-list`）时，顺带提示有奖券未核销的订单。

## 策略 11：全渠道比价 —— 官方渠道 vs 美团/抖音团购

```
[官方侧] calculate-price → 得到"商品合计原价 + 带券最优实付"
[团购侧] 用户在美团/抖音 App 查询麦当劳团购券
         → python scripts/deal_compare.py add --platform meituan --title "..." \
             --price 25.9 --face 40 --channel store --time limited ...
         → python scripts/deal_compare.py compare --mcd-face 48.5 --mcd-price 38.5
[决策]   报告输出推荐：官方渠道 或 团购券（含估算节省与限制提示）
```

- 数据获取方式：团购平台无公开 API，券信息由用户**手动录入**本地券库；
  比价结果为**估算值**，须向用户明确标注。
- 团购券通常**不可叠加**官方优惠券与积分抵扣，决策口径必须一致。
- 推荐团购时提示核对：适用门店范围、可用时段、是否含配送费、退改规则、
  订单内容是否被券面值覆盖。
- 方法论详见 `references/group-buy-comparison.md`。

## 省钱检查执行矩阵

| 场景 | 必做 | 可选 |
|---|---|---|
| 任何下单前 | 策略 2、3 | 策略 1、4、5 |
| 外卖/到店首单会话 | 策略 1 | 策略 5、7、8 |
| 用户问"怎么最划算" | 策略 3、5 | 策略 6、7 |
| 企业团餐 | 策略 9 | 策略 3 |
| 积分较多/临期 | 策略 5、8 | — |
| 查历史订单 | 策略 10 | 策略 6 |
