# 一单三种买法：可复现算例

> 用**同一份订单**跑出「单点 / 官方券 / 团购券」三种买法的实付，并说清差价来自哪里。
> 全部命令离线可跑，**不需要 MCP Token**；三组金额均来自命令实际输出，不是手写估算。
> 估算口径说明：本地计价未经官方 `calculate-price` 验证，真实价格以下单前接口返回为准。

## 本单设定

- 购物车与内嵌 fixtures 一致，原价合计 **¥33.50**；
- 门店可用券（fixtures）：满30减6、到店取餐9折券、满40减10；
- 团购券（手动录入）：美团「麦当劳满40减14代金券」，售价 ¥25.90 / 面值 ¥40.00。

## 第一步：单点与官方券

```bash
python scripts/optimizer.py demo
```

实际输出：

```text

====================================================================
基准（无券直点）：¥33.50

方案排名：
  1. 满30减6
     实付 ¥27.50 ｜ 热量 940 kcal ｜ 省 ¥6.00（18%）  ← 最优 ｜ 最经济
```

读数：

- **单点（无券直点）：¥33.50**；
- **官方券最优：¥27.50**（满30减6，省 ¥6.00 / 18%），领券即用、零额外成本；
- 注意第 3 名「满40减10」：面值更大（减 ¥10）但实付更高（¥30.50）——因为要凑单加脆薯饼，
  多买的钱超过了多减的券面。**券面值大 ≠ 省钱**，这是凑单陷阱的典型形态。

## 第二步：团购券

⚠️ 常见坑：`deal_compare.py --file` 需要**顶层是数组**的本地券库，而 `fixtures/deals.json`
是 MCP 返回格式（`{"deals": [...]}`），直接指过去会得到空券库且不报错。请用 `add` 新建：

```bash
python scripts/deal_compare.py --file deals.json add \
  --platform meituan --title "麦当劳满40减14代金券" --price 25.9 --face 40
```

实际输出：

```text
已录入团购券 [c8e091] 麦当劳满40减14代金券（meituan）
```

> 券编号每次随机生成，重跑会得到不同 ID，属正常现象。

与官方最优方案同口径对比（`--mcd-face` 传同内容原价，`--mcd-price` 传官方带券最优实付）：

```bash
python scripts/deal_compare.py --file /tmp/deals.json compare \
  --mcd-face 33.5 --mcd-price 27.5
```

实际输出：

## 三种买法汇总

| 买法 | 实付 | 较单点省 | 性质 |
|---|---:|---:|---|
| 单点（无券） | ¥33.50 | — | 基准 |
| 官方券（满30减6） | ¥27.50 | ¥6.00（18%） | 领券即用，确定收益 |
| 团购券（美团满40减14） | **¥21.69**（估算） | **¥11.81（35%）** | 需先花 ¥25.90 购券；不可与官方券叠加 |

## 结论：这单该怎么点

1. **官方券是保底选项**：¥27.50 零额外成本、领券即用，`optimizer.py demo` 已给出最优券。
2. **团购券看覆盖，不看折扣率**：估算到手 ¥21.69，比官方最优再省 ¥5.81；但该券门槛为
   「满 40 减 14」，本单内容 ¥33.50 未达标——若要走这条路，需把购物车凑到 ¥40 并重跑一次
   对比，且凑单部分只用你本来就会买的东西。若券已售罄或门店不符，回退官方渠道。
3. **凑单陷阱的判据**：第 3 名方案（满40减10）实付 ¥30.50 反而高于第 1 名（¥27.50）——
   为凑门槛多买的脆薯饼吞掉了多减的券面。判据是「加购金额 − 多减券面」是否为负。
4. 所有金额为本地估算；真实价格以 `calculate-price` 实测与各平台页面为准。
