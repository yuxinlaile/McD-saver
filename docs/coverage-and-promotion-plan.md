> 生成于 2026-10-19。覆盖率口径：`pytest --cov=scripts`（仅统计 `scripts/` 下的运行时代码，
> 不含 `demo.py`、测试自身与 `__main__` 保护块）。

## 一、覆盖率为什么不是 100%

|---|---|---|---|

### 1.3 五类根因

- **A 进程入口**：`main(argv)` 与 `if __name__ == "__main__"` 只在命令行触发，pytest 直接 import 不会执行。
- **B 命令主干**：`deal_compare` / `optimizer` / `silent_cost` / `version` / `build_releases` 的 CLI 分支此前只有 `--help` 冒烟。
- **C 外部依赖**：真实 HTTP（MCP Server）、`git archive`、`gh api` 上传——CI 不应访问生产服务。
- **D 平台分支**：POSIX 文件权限检查在 Windows runner 上不执行；`os.name` 判断天然单侧覆盖。
- **E 防御分支**：IO 失败、JSON 解析失败、空数据、参数错误等，需要专门构造异常输入。

### 1.4 为什么不应追求 100%

| 不可达/不该测的部分 | 原因 | 替代验证 |
|---|---|---|
| `if __name__ == "__main__"`、argparse 帮助/错误文本 | 执行即 `SystemExit`，断言价值低 | CLI 冒烟（`--help` 退出码）+ 子进程测试 |
| 真实 MCP 网络调用、`gh` 上传 | CI 不应依赖外部服务与凭据 | 假 `urlopen` 测试分支 + `examples/verified-run.md` 真实留档 |
| `git archive` 打包路径 | 依赖 tag 与 git 环境 | 本地 `--verify` + Release 资产校验 |
| 平台专属分支 | Windows/Linux 只能覆盖其一 | CI 矩阵（3.9/3.11/3.13）覆盖解释器差异，平台差异靠代码审查 |

**合理目标：85%–90%，且关键路径（金额计算、券排程、错误映射、CLI 退出码）要求 100%。**

## 二、可执行的改进方向

### P0 · 已完成（+13pp，62% → 75%）

- `tests/test_client_http.py`（19 项）：假 `urlopen` 覆盖 JSON/SSE 解码、会话头、401/429/5xx 重试、网络异常、工具错误、关闭会话。
- `tests/test_cli_commands.py`（21 项）：桩客户端覆盖 `check` / `tools` / `schema` / `call` / `claim` 与四类错误退出码；`verify_run` 的 Token 缺失、连通失败、Markdown/HTML 生成。
- **顺带修复真实缺陷**：JSON-RPC `error` 响应此前被 `_jsonrpc` 当成「无结果」抛出 `TransportError`，导致 `call_tool` 的错误分支不可达、错误码丢失；现改为交由调用方按 `error` 处理。

### P1 · 预计 +8~10pp（→ 83%–85%）

| 任务 | 覆盖目标 | 做法 | 预计语句 |
|---|---|---|---|
| `deal_compare` CLI | 38% → 85% | `tmp_path` 建券库，跑 `add` / `list` / `compare`，断言排序与退出码 0/1/2 | +90 |
| `optimizer` CLI | 75% → 90% | `estimate` / `demo` / `plan` 参数组合；`--no-deals`；`--mcp` 用 `prefilter_plans` + 假 pricer | +60 |
| `silent_cost` CLI | 80% → 92% | `--html` 写临时文件、`--probe` 打桩、空数据/无券分支 | +50 |

### P2 · 预计 +5pp（→ 88%–90%）

| 任务 | 覆盖目标 | 做法 |
|---|---|---|
| `version` CLI | 80% → 100% | 合法/非法/超限输入、`--apply` 指向 `tmp_path` 仓库 |
| `build_releases` | 53% → 75% | `--index` / `--verify` 失败分支；`git` 与 `urlopen` 打桩，**不发起真实上传** |
| `check_toc` 失败分支 | 85% → 100% | 临时 README 制造死链、章节缺失、中英数量不一致 |

### 执行纪律

1. 每个改动只加测试、不改业务逻辑；确需修 bug 单独提交并写清原因。
2. 覆盖率门槛分两步提：`55% → 75%`（下一次发版）、`75% → 85%`（定榜后）。
3. 验收命令：`pytest tests/ -q --cov=scripts --cov-fail-under=<门槛>` + `scripts/check_toc.py`。
